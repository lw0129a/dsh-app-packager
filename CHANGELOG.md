# Changelog

All notable changes to this project are documented here. Both published packages share a version number.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.7.0] - 2026-10-29

### Changed

- **更新插件改成「先关旧版，再安装」：** 面板点「升级插件」时不再挂一条等着装完的任务，而是先停掉在跑的任务、撤掉插件自己注册的全部路由（旧版本当场关闭），再由 `dist/upgrade.js` 在后台独立进程里跑安装，输出写进 `home/logs/upgrade-<时间>.log`；关闭之后面板不再接受新任务，装完重启 DeepSeek Harness 生效。宿主没有重载插件的 API，所以「新旧同时在线」是做不到的，旧版必须真的下线。
- **升级失败不再丢引擎目录：** 安装进程如果在暂存 `home` 与恢复之间被杀（SIGKILL、关终端、pnpm 失败），下次启动由新增的 `recoverUpgradeBackup()` 把 `.app-packager-home-backup` 认领回 `home`；已有 `home` 时只提示、绝不覆盖。离线 SDK、证书、项目配置不再需要人肉搬。
- **自动升级能找到 `dsh` 了：** 以前只试 `/usr/local/bin/dsh`，Homebrew（`/opt/homebrew/bin`）或自定义 `PATH` 的机器会掉到 `pnpm add` 装错地方。现在按 `DSH_BIN` → `/usr/local/bin` → `/opt/homebrew/bin` → `PATH` 顺序查找，全都找不到才退回 pnpm 并提示。
- 插件图标：蓝色渐变（`#57B0FF` → `#1B4FD6`）+ 白色等距包裹，`package.json` 增加 `icon` 字段；侧栏图标换成同一剪影（等距箱 + 顶面淡填充，18px 下不放箭头）。描述改中英双语。

### Added

- 测试：升级关闭流程（停任务、撤路由、后台安装、关闭后拒收任务）、HTTP 层升级请求后路由归零、升级备份自愈——插件侧 46 例。

## [0.6.10] - 2026-10-24

### Fixed

- **插件被重复挂载时不再抛 `webserver: duplicate exact route "/api/app-packager/state"`。** 插件市场更新会在同一个宿主进程里二次 apply 插件，旧版本每次都重新注册同一批 exact route，宿主抛错后更新失败并回滚。`packages/dsh-app-packager/src/web.ts:1219` 起新增 `mountedServers` WeakSet 守卫：同一个 webServer 只挂一次，重复挂载返回空 disposer，dispose 时释放以便之后重挂。新增 1 例测试（插件侧 43 例）。

### Changed

- **引擎迁移第 4 批：证书与上传层进 TypeScript。** 新增 `src/engine/certificates.ts`（对应 `engine/lib/certificates.sh`，610 行全量移植：就绪判定、证书源目录扫描与规范化改名、同名覆盖前归档到 `logs/certificate-history/<时间戳>/<平台>/`、平台清理与单文件删除、`cert-status` 的 JSON 契约不变）与 `src/engine/upload.ts` + `src/engine/uploaders/pgyer.ts`（平台清单解析、构建后上传与失败不中止语义、`latest.json` 产物发现、pgyer CLI 上传与 HarmonyOS HAP 走接口上传）。HTTP 从 `curl` 换成内置 `fetch`，不再依赖外部 uploader 脚本。新增 17 例测试。

## [0.6.6] - 2026-10-19

### Added

- **证书板块可以整平台清理、也能删单个文件。** 面板每个平台多一个「清理」、每行证书文件多一个「删除这个文件」（都二次确认），分别走新增子命令 `cert-clear <ios|android|harmony>` 和 `cert-remove <平台> <文件>`：只归档不删除，把 `certificates/<平台>/` 下的文件挪进 `logs/certificate-history/<时间戳>/<平台>/`，导错了手动挪回来即可，清理后该平台证书状态回到未就绪；项目自己配置的证书（`PROFILE_FILE`、`P12_FILE`、`signingConfigs`）和证书来源目录都不动。
- **新增微信小程序平台（`mp-weixin`）。** `build mp-weixin <项目ID>` 一条命令编译 + 上传微信公众平台：直接调 HBuilderX `cli publish --platform mp-weixin`，不需要微信开发者工具、不扫码，上传凭证用「微信小程序代码上传密钥」（`certificates/WeChatMP/*.key` 或 `MP_WEIXIN_PRIVATE_KEY`），AppID 读 `manifest.json` 的 `mp-weixin.appid`（可被 `MP_WEIXIN_APPID` 覆盖），版本号、描述、机器人编号都可覆盖。产物归档到 `packages/MPWeixin/<项目ID>-<AppID>-<版本>-<时间戳>/mp-weixin`（不压缩，小程序是目录不是安装包）。`--no-upload` 只编译不上传；`check mp-weixin` 校验 HBuilderX ≥4.41、AppID、上传密钥并提示 IP 白名单。小程序刻意不进 `all`：它不产出安装包、上传也是内联在构建里，混进「全部平台」会打乱别人的批量习惯；菜单和面板各自单列一项。配套文档 [微信小程序打包](docs/zh-CN/mp-weixin.md) / [English](docs/en/mp-weixin.md)。**面板同一流程可操作**：勾选平台「微信小程序」后打包卡片出现「构建后上传微信公众平台」复选（映射到新增的 `--mp-weixin-upload true|false`，`check` 也认，预检按同一开关决定是否强制要求密钥），产物列表统一收录 `packages/MPWeixin/` 并以「已上传微信后台 / 仅编译」标状态，因为小程序是目录所以不提供单文件下载按钮。
- **`build` / `check` 可以转发到另一台 macOS 执行，产物自动拉回。** Windows 上打不了 iOS，买第二台 Mac 或上云又不划算，所以新增 `--remote user@host[:端口]`：命令经 `ssh` 在远端引擎目录里跑 `打包工具.command`，成功后用 `scp` 把 `packages/<平台>` 拉回本地，配 `--remote-key` / `--remote-home` / `--no-pull` 三个开关。远程命令的每个参数都做 POSIX 单引号转义，`~` 交给远端展开，默认 `BatchMode=yes`，密钥没配好会立刻失败而不是挂住。`src/remote.mjs` 是纯函数 + 两个 spawn，测试用一个假 `ssh` 断言 argv（Windows 上跳过）。配套文档 [Windows 上用 macOS 虚拟机打 iOS 包](docs/zh-CN/windows-ios-vm.md) / [English](docs/en/windows-ios-vm.md) 写了 VMware + macOS 的下载地址、安装步骤、SSH 打通与常见坑。

## [0.6.5] - 2026-10-19

### Fixed

- **`doctor` 不再给不存在的 HarmonyOS 签名目录打 ✓。** `harmony.signing` 这一行原先只判断 `HARMONY_SIGNING_CERT_DIR` 有没有值，有值就把该路径当 `ok` 打出来——全新物化的引擎 home、或在 `init` 建目录之前，路径并不存在，报告却是一片绿，等到真要打包才在签名阶段失败。现在和旁边的 `android.sdk` / `ios.hbuilderx` 一样先 `fs.existsSync`：目录缺失报 `warn` + `… 不存在` + 放置证书或改配置的提示，目录存在才报 `ok`。`packager.test.mjs` 补一例（先缺失后 `mkdir`，断言 `warn` → `ok`）。

## [0.6.4] - 2026-10-11

**The engine no longer dies printing Chinese on a Windows console.** `engine/lib/common.sh` exports `PYTHONUTF8=1` and `PYTHONIOENCODING=utf-8` for every engine process. Windows `python3` encodes stdout with the local code page (cp1252 / cp936) unless told otherwise, so any engine step that printed Chinese raised `UnicodeEncodeError` mid-run — CI's Windows legs caught it in `android_agp_effective_version` (the `keep 9.3.2 (requested 8.12.0 跨 AGP 大版本)` line). macOS and Linux were already UTF-8, so the export is a no-op there.

**The test suite is portable again.** The JSONC round-trip assertion now reads the normalized file with `grep` instead of a `python3 -c` that embedded a POSIX `/tmp/...` path (MSYS does not rewrite a path that sits inside a code string, so native Python could not open it), and the download-destination test builds its expectation from `os.tmpdir()` instead of a hardcoded `/tmp/dl` (on Windows `path.join('/tmp/dl', 'a.apk')` is `D:\tmp\dl\a.apk`). `pnpm-lock.yaml` also caught up with `workspace:^0.6.3`, without which CI's `pnpm install --frozen-lockfile` aborted with `ERR_PNPM_OUTDATED_LOCKFILE`.

## [0.6.3] - 2026-10-11

### Added

- **An installer that is already archived can be downloaded from the panel, and where it lands is one setting.** Every row of the *Upload* card (which reads exactly what `<home>/packages/<Platform>/*-latest.json` names) gains a **Download** button that posts `{platform, project, dir}` to `POST /api/app-packager/download`; the host finds that artifact with `listArtifacts(home)` and copies it with `fs.promises.copyFile`, answering `{ok, platform, project, saved, dir, size}`, and the panel prints the saved path under the row. The destination is the card's new **Download folder** row: an input pre-filled from `state.downloadDir` (the host's `DEFAULT_DOWNLOAD_DIR`, i.e. `~/Downloads`), a *Choose folder…* button that reuses `POST /api/app-packager/pick`, and a hint explaining that a blank value falls back to the default. `downloadDestination(dir, fileName)` expands a leading `~`, treats a blank value as the default, and never overwrites: an existing name gets `-1`, `-2`, … appended to its stem, so downloading the same build twice keeps both files. The folder is remembered per browser in `localStorage['ap-download-dir']` and nowhere else. `plugin.test.mjs` pins the path helper (blank / `~` / collision) and does a real copy twice to prove the second one lands as `…-1.apk` and that a missing artifact rejects.

- **Classic uni-app projects (uni-app + Vue, i.e. no `uni-app-x` key in `manifest.json`) build Android APKs locally now.** New `project_is_uniappx()` drives a flavor split through the Android pipeline, which until now assumed uni-app x step by step: the resource step runs `HBuilderX publish app --type appResource` and reads `unpackage/resources/<appid>/www` instead of `publish app-android` + `unpackage/resources/app-android`; `copy_android_resources()` drops that `www` into `<module>/src/main/assets/apps/<appid>/www` (the HBuilder-Integrate-AS / HBuilder-HelloUniApp layout) and rewrites `assets/data/dcloud_control.xml` to name the project's appid instead of copying uni-app x Kotlin sources into `uniappx/`; `sync_android_permissions()` falls back to the `app-plus` permission block when there is no `app-android` one; `patch_android_project()` also patches the `"apk.applicationId"` manifest placeholder; and `apply_android_brand_assets()` (which targets `uniappx/src/main/res`) stays out of the way. Such a project keeps **its own Gradle wrapper** — the AGP 8 template cannot run on the cached Gradle 9, and `check android` now reports `Gradle: 项目自带 Wrapper（经典 uni-app，构建时使用）` instead of probing `--version` (which would trigger a 130 MB wrapper download) — and **its own JDK**: with a JDK 24+ default, Gradle 8 dies in semantic analysis (`Unsupported class file major version 69`), so the classic path selects JDK 21/17 through the new `classic_android_java_home()` (`ANDROID_CLASSIC_JAVA_HOME` in `config/settings.env` pins one explicitly) and says so in the log. Verified end to end on a classic `hello-uniapp` project: `com.example.hellouniapp` 1.0.0, 71 MB APK, `assets/apps/__UNI__98CDDE3/www/app-service.js` in place, signed with the template's own test keystore. **iOS and HarmonyOS remain uni-app x only** — Android is the one platform with two working local paths, and HBuilderX cloud packaging (`cli pack`) is the alternative for classic projects.

### Changed

- **The panel no longer calls every project a "uni-app x" project, and neither does the engine.** Fifteen strings that labelled generic behaviour as x-specific became `uni-app 项目` (`lib/common.sh`, `lib/runner.sh`, `lib/init.sh`, `src/cli.mjs`, `src/doctor.mjs`), and `app-packager --help` now titles itself `uni-app / uni-app x 打包命令行`. The strings that really are x-only were left alone: iOS local packaging still requires `UniAppXDemo.xcodeproj`, HarmonyOS still installs the `@dcloudio/uni-app-x-runtime` ohpm package, and the `ShareWithSystem` bundle id is still an x-only detail.

### Fixed

- **A JSONC `manifest.json` no longer costs a classic build its whole permission set.** The classic template ships `/* … */` comments in `manifest.json`, and the strict `json.loads` in the full-permission merge (`PY_FULL_PERMISSIONS`) raised `JSONDecodeError` — while the build carried on, because `sync_full_permissions()` is called from an `if` condition where `errexit` is suspended, so the failure never reached `die`. The result was a silent downgrade: the same project produced **69 permissions before the fix and 89 after**, the full-permission profile (`FULL_PERMISSION_PROFILE=true`) having been dropped on the floor. `manifest_jsonc_to_json()` now runs in `prepare_workspace()` right after the project is copied into the isolated workspace: a string-aware scanner strips `//` and `/* */` comments and trailing commas, writes the file back **only** when the result actually parses, and leaves anything it cannot clean untouched — `"url": "http://…"` keeps its slashes, the business project's own file is never modified, and the panel log prints `manifest.json 已规范化为标准 JSON` when something was normalized. `engine.test.sh` pins normalization, the in-string `//`, idempotence, and the untouched broken input.

- **A `$variable` immediately followed by a Chinese character no longer aborts a build with `unbound variable`.** bash parses the multibyte character as part of the name, so `log "…（$flavor，静默模式）"` dereferenced a variable actually named `flavor，` and `set -u` killed the first classic Android build at `common.sh:1904` before HBuilderX was even called. `${flavor}`, `${APP_ID}` and (in the pgyer HAP path) `${profile_distribution}` now end their names explicitly — that last one was a real pre-existing bug, the warning branch for a mismatched distribution type could never print. `engine.test.sh` walks every engine shell file for `$name` directly followed by a non-ASCII byte, so the class cannot come back.

## [0.6.2] - 2026-10-10

### Added

- **This plugin repo now guards itself against business project configuration.** `scripts/check-no-local-config.mjs` (`pnpm guard:check`; also the first half of `pnpm test`, and `.githooks/pre-commit` once `git config core.hooksPath .githooks` is set) walks the files git actually tracks and refuses a real project config (`<engine>/config/projects/*.env`), a machine-local override (`config/{settings,init,upload,parallel}.local.env`), signing material (`signing/current/`, `certificates/`), run logs, tool/SDK/package directories, any key, certificate or installer extension, and any file whose body contains a PEM private key. Zero dependencies.
- **Uploading is its own panel section, and pgyer now takes a User Key as well as an API key.** *Build options* hands its credential row over to a new **Upload** section (its own card between the build card and the job card) and keeps the uploader checkboxes, moved under **Upload after build** — that row edits the very same selection the Upload card's *Distribution* row does, so ticking 蒲公英 there uploads what the build just produced and ticking nothing sends `noUpload` — while the Upload card works only on what the engine has already archived: `state.artifacts` comes from a new `listArtifacts(home)` that reads `<home>/packages/{iOS,Android,HarmonyOS}/*-latest.json` and reports platform, project, version, build time, installer path, `artifactExists` and size. Each row shows `display name version` with its size (or a *no installer archived* tag when the JSON survived but the file did not) and an *Upload* button that starts a `kind: 'upload'` job for that one artifact and the ticked distribution platforms; the card footer holds one credential row per secret — `apiKeyVar`/`credentialConfigured` as before, plus the new `userKeyVar`/`userKeyConfigured` (`UPLOAD_PLATFORM_pgyer_USER_KEY_VAR`, pgyer's API 1.0 `uKey`) — and every row carries a `已配置` / `未配置` chip driven by that boolean, so a key that is still missing is visible up front instead of only at the save button. Each secret is saved on its own through `POST /api/app-packager/upload/credential`, which now accepts `apiKey`, `userKey` or both and writes only the fields it is given, so storing one never clears the other.
- **The pgyer API key is now filled in from the panel, and stored where the engine already looks.** Every uploader that declares one gets a credential row (`UPLOAD_PLATFORM_<id>_API_KEY_VAR`, pgyer declares `PGYER_API_KEY`) — it sat under *Build options* until the upload card took it over; saving posts to `POST /api/app-packager/upload/credential`, which writes `<home>/config/upload.local.env` (mode 600, other lines kept, an empty value clears the entry) — the file `lib/init.sh` sources right after `upload.env`, so the value never has to be exported by hand. The value only travels engine-ward: `listUploaders` exposes `apiKeyVar` and a boolean `credentialConfigured`, never the secret, and the panel shows a `已配置` tag plus a masked input whose placeholder changes once a key is stored. The same row also reports whether the pgyer CLI is already installed (`state.pgyerCli`), so the first upload is the only one that mentions installing it.

### Changed

- **The panel no longer tells you to reload the page after a plugin upgrade, because that is what made the sidebar entry disappear.** DSH serves a client plugin at `plugins/??<id>/client.js&rev=<hash>` and rejects an unknown revision: measured, a stale `rev` answers **404** (0 bytes) while the live one answers 200. The revision in a loaded page comes from the manifest built when DSH booted, so after the plugin package is replaced on disk a reload asks for a revision the server can no longer produce — the client half fails to load and **the AppPackager row vanishes** until DSH restarts and the manifest is rebuilt (exactly the trap the old advice pushed people into). The post-upgrade notice now says *restart DeepSeek Harness*, the *Reload page* button and its dictionary key are gone, and both READMEs explain the revision-404 mechanism.
- **The build workspace follows the DSH profile now.** `relocate_work_root_out_of_node_modules` still has to move the workspace out of `node_modules` (HBuilderX 5.26's Android compiler rejects such paths), but for the DSH plugin layout it now uses `<profile>/.app-packager/workspaces` instead of `~/Library/Caches/app-packager/workspaces`; the system cache stays as the fallback for non-DSH layouts and `APP_PACKAGER_CACHE_ROOT` still wins. Engine script version `2026.10.10.12`. The old cache directory is no longer written and can be deleted.
- **Build options and build scope are one card now.** They were two halves of the same decision — how to build (version, iOS kind, profile, full permissions, custom `KEY=VALUE`, the *Advanced* fold, *Upload after build*) and what to build (platforms × projects plus the *Env check* / *Build* pair) — so the panel now shows them as a single foldable card titled `打包选项 · 打包范围` / *Build options · Build scope*, with the scope kept in its own boxed block at the bottom and the scope hint inside that block (so a collapsed card still shows nothing but its title). One fold less to open before a build, and the two settings that always had to agree can no longer be open in two places at once.
- **No business identifiers are left in the published sources.** Sample paths, sample project names, the Keychain examples and the test fixtures now use neutral values (`/Users/you/work/projects`, `demo-app`, `com.example.demoapp`), while `P12_PASSWORD_SERVICE` / `HARMONY_P12_PASSWORD_SERVICE` keep their defaults in `config/settings.env` — the docs reference the variable names instead of pasting the values. Both `.gitignore` files also cover `*.pfx`, `*.provisionprofile`, `*.jks`, `*.keystore`, `*.p7b`, `*.p8`, `*.pem`, `*.key`, `*.cer` (Apple's two root CAs excepted) and `*.ipa` / `*.apk` / `*.hap` / `*.tgz`.
- **Every panel section now starts folded, and the environment check runs itself.** All seven cards (Engine / Environment check / SDK / Projects / Build options & scope / Upload / Job) open collapsed, so entering the panel is a clean list of titles; the fold state still lives with the component, so a state refresh or a job-log poll never loses or resets the user's choice. The *Environment check (Node)* card used to sit on `加载中…` until someone pressed *Run check* — it now fires by itself as soon as the engine state arrives (and again when the platform picker inside that card changes; the effect depends on a plain boolean rather than the state object, so the check does not re-run on every refresh), without taking the panel's busy flag, and a failed check writes the reason into the card, where *Run check* retries.

- **Packaging and uploading are two flows now.** `打包工具.command upload ios|android|harmony|all <项目ID> [--to <平台>]` ships the installer the *last build* archived (`<home>/packages/<Platform>/<项目ID>-latest.json`, then whatever installer that file names) and never rebuilds; with nothing archived it only warns (`上传跳过：… 还没有打包记录（…），先打包一次`). `--to` picks the distribution platforms and defaults to the enabled ones in `config/upload.env`. In the engine this is `upload_latest_artifact` → `run_post_build_uploads <info> [strict]`: builds still upload when asked — the panel sends that `--upload` from the *Upload after build* row in *Build options* — but a failed upload there stays a non-event and never changes the build's exit code, while the standalone action returns the real status. The pgyer CLI call now also passes `PGYER_USER_KEY` through when one is configured, and the HAP API calls carry `_u_key` in the token, certificate and poll requests.
- **Uploading to pgyer now goes through the official CLI instead of a hand-written curl call.** iOS/Android used to POST a multipart form (`_api_key`, `buildType`) to `upload.pgyer.com/apiv2/app/upload` from `engine/lib/uploaders/pgyer.sh`; they now run the official `@pgyer/cli` (command `pgyer`) fast upload: `pgyer upload <file> --json --timeout … --poll-interval …`, with `--build-update-description` when a description is set and `PGYER_INSTALL_PASSWORD` + `--password-env` for an install password. The key is handed over as the `PGYER_API_KEY` environment variable only, so nothing writes `~/.config/pgyer/config.json` and `pgyer auth login` is never needed. The CLI is installed lazily and privately: not globally, not up front, but `npm install --prefix <engine home>/tools/pgyer-cli @pgyer/cli@<version>` the first time an upload actually runs (`PGYER_CLI_DIR` / `PGYER_CLI_PACKAGE` / `PGYER_CLI_VERSION` override the location, package and pinned version `0.1.5`; `tools/*` joined the home `.gitignore`), which keeps it inside the plugin's own data directory — SDKs, certificates and projects are untouched by plugin upgrades as before. Its stdout/stderr land next to the other upload evidence (`logs/uploads/pgyer/*.cli.json` / `*.cli.log`) and the mapped result gains a `cli` field naming the package and binary. **HarmonyOS HAP still uses the API implementation**: pgyer requires the P12 certificate alongside a HAP (`uploadHarmonyCert`), which CLI 0.1.5 has no step for (it only recognises `.hap` by extension), so the `harmony` branch keeps calling `pgyer_upload_harmony_artifact`. `PGYER_API_BASE_URL` and `PGYER_LEGACY_UPLOAD_URL` are gone with the curl path. `engine.test.sh` pins four things: the CLI lives inside the engine home by default, an already-installed CLI never calls npm (a deliberately failing fake `npm` proves it), `PGYER_CLI_DIR` moves it, and the iOS/Android dispatch really is the CLI one with the old curl function deleted.

- **A running job is no longer invisible after you switch panel tabs.** The job runner lives in the host process (`createJobRunner` in `web.js`), but the browser half kept the job in a `useState` of the panel component — so switching to another DeepSeek Harness tab (or any remount) dropped the log, the verdict and the *Stop* button while the build kept running in the background. The panel now adopts the newest job from `GET state` (`state.jobs[0]`) whenever it does not already own a running one, which also restores the 1.2 s log polling. Finished jobs stay on screen until you start another build or press the new *Clear* button (`POST /api/app-packager/job/clear`, `runner.clear()`); clearing only ever drops settled jobs — a running one is never removed, or there would be nothing left to signal.
- **Each SDK row now names the archive to download, not just the page that lists it.** A platform row shows the `package` field the engine already returns (`sdk urls` prints the same value), so a manual download can be matched to the series without guessing: Android's name carries its build number, HarmonyOS is labelled `ohpm 包名` because `@dcloudio/uni-app-x-runtime` is a DevEco ohpm package that `npm` cannot resolve.
- **The panel now says what to do after an in-panel plugin upgrade.** An upgrade replaces the very package the host loads, and the client module scan is incremental per package and only ever reads loader entries that still have a live fiber — so the browser half (sidebar entry included) only comes back on the next page load. A successful `upgrade` job now shows a heads-up in the job card with a **Reload page** button (`location.reload()`), and points at a DeepSeek Harness restart as the fallback. The reload stays a button on purpose: reloading automatically would throw away a build log the user may still be reading.

### Changed

- **The project list is one foldable section, and build options got a section of their own.** What was wanted was *one* switch for the whole list, not an arrow per project: the card is now titled `项目列表 / Project list`, folding it hides every registered row, and each row keeps its own two-step `删除` button on the row itself (a project is not its own collapsible block). The build options that used to be squeezed into the same card — upload targets, version, iOS release kind, provisioning profile, full-permission switch and the advanced fold with custom `KEY=VALUE` parameters — are now the `打包选项 / Build options` section, with the `打包范围 / Build scope` block inside it (the two were later merged into the single *Build options · Build scope* card). Picking several folders in the OS dialog still works (they are joined into that one field, and the engine splits on comma).
- **Every panel section can now be folded away.** Engine, environment check, SDK, project list, the build card (options plus scope), upload and job cards each carry a header button with an arrow (`aria-expanded` follows the state) that hides just that card's body, so a long SDK list no longer pushes the job log off screen; the arrows live outside the action row, so hitting `刷新` no longer folds the card as a side effect. - **The panel got a proper layout, and it scrolls again.** It was a stack of inline-styled flex rows: label/value pairs drifted apart, long SDK paths pushed the `一键配置` buttons into a vertical squeeze, check hints ran on next to the text, and the whole page could not be scrolled at the bottom because `.ap-root { height: 100% }` resolves to `auto` as soon as any wrapper in the host's slot chain has an auto height — so the host's `overflow: hidden` simply cut the rest off. Layout now lives in class names (cards, a two-column label/value grid, one block per SDK platform with the archive/path lines beneath it, a sticky header), and scrolling has two legs: `.ap-root` scrolls when the parent chain gives it a height, and a measured effect flips the nearest clipping ancestor to `overflow-y: auto` (restored on unmount) when the chain is broken.
- **The HarmonyOS line of `sdk urls` / `sdk text` is now labelled as an ohpm package** (engine script version `2026.10.10.5`). All three platforms shared the `文件名/包名:` label, so HarmonyOS printed `@dcloudio/uni-app-x-runtime@5.26.*`, which reads like an npm package; it is a DevEco **ohpm** package (`npm view` answers 404) that `ohpm install` unpacks into `sdk/HarmonyOS/<series>/oh_modules`. That line now reads `ohpm 包名: …（DevEco Studio 的 ohpm 仓库，不在 npm 上）`, matching the wording the interactive init flow already used.

### Fixed

- **The build queue's progress line no longer disappears on Windows.** The queue renderer's inline Python printed the status row (e.g. “等待 HBuilderX 名额”) through Windows' default cp1252 stdout, so Python raised `UnicodeEncodeError` and the whole line was lost — a Windows user saw the build go quiet after “构建队列” with no hint of progress. Both renderers now pin stdout to UTF-8 (`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`), with a test that forces `PYTHONIOENCODING=cp1252` to keep it honest. The `config/upload.local.env` mode-600 assertion is POSIX-only as well, since Windows has no POSIX mode bits and that made CI's Windows leg red.
- **A skipped upload is no longer reported as success** (engine script version `2026.10.10.10`). `run_post_build_uploads` had two early returns that ignored its `strict` argument — "no build info file" and "build info has no `platform`" both warned and returned 0 no matter what — so the standalone `upload` action could exit 0 having sent nothing at all. Measured before the fix: `app-packager upload ios <项目> --to pgyer` against an iOS archive written by the engine that did not yet store `platform`, printing `打包结束，退出码: 0` while `pgyer versions list <appKey>` showed the newest iOS build still at `2026-10-04 16:33:32` and `logs/uploads/pgyer/` held no record for that minute. Both early returns now respect `strict` (`[ "$strict" = "true" ] && return 1`), so a standalone upload fails loudly when it skipped, while a build-time upload — `strict` defaults to false — keeps its old "warn but never touch the build's exit code" behaviour. `engine.test.sh` pins all three cases with a stale archive fixture.
- **`app-packager --dir <路径> <引擎动作>` no longer hands `--dir` to the engine.** The passthrough branches forwarded the raw `argv`, but `parseArgs` had already consumed `--dir` as a plugin-only flag, so the engine answered `ERROR 未知参数: --dir` instead of doing the work — true for `upload` and equally for `ios` / `android` / `harmony` / `all`, and unrelated to the upload work that surfaced it. The plugin-only flags now have a name (`PLUGIN_ONLY_FLAGS`) and an `engineArgv(args)` helper drops them — and the value that follows a value-taking one — inside `withEngine`, which every engine entry point already routes through, so one guard covers `run`, the platform shortcuts, `upload` and the unknown-command passthrough alike.
- **iOS uploads are no longer silently skipped** (engine script version `2026.10.10.9`). `run_post_build_uploads` dispatches on the `platform` field of `build-info.json`, and the iOS writer never emitted one, so every iOS upload ended as `上传跳过：构建信息缺少 platform` while Android and HarmonyOS worked — with `--upload pgyer` on the command line and the key configured. `lib/common.sh` now writes `platform: "ios"` as the first key of the iOS build info, and `engine.test.sh` proves the whole standalone path (`parse_args upload … --to …`, artifact lookup, provider success/failure, and that a build-time upload failure still leaves the build's exit code alone) against a stubbed provider instead of the network.
- **Android builds no longer fail for every project when the engine is installed through npm** (engine script version `2026.10.10.7`). HBuilderX 5.26's Android resource compiler refuses a project that lives under a path containing `node_modules`: it treats such a path as a dependency, so the relative import the compiler generates itself (`./uni_modules/<plugin>/instans/types`) dies with `failed to resolve … index not found` inside the `.uvue/app-android/main.uts` it had just written. The npm distribution layer keeps the engine at `<profile>/node_modules/dsh-app-packager/home`, which put every build workspace inside `node_modules`, so Android failed while iOS/HarmonyOS (a different compile chain) succeeded from the very same directory. Reproduced from the command line: an identical copy of the project compiled fine in `/tmp` and failed as soon as the directory was moved under a `node_modules` path; `uni_modules`, `node_modules`, `unpackage`, `app-ios` and the two engine patches (`App.uvue` permission bootstrap, `manifest.json` full-permission merge) were each ruled out first. `lib/common.sh` now defines `relocate_work_root_out_of_node_modules` and both entry points call it once the `config/*.env` files are read — `init.sh` and `runner.sh`, because the panel/CLI build entry is `runner.sh`, which sources `settings.env` itself and never passes through `init.sh` (patching only `init.sh` is exactly how the first attempt still failed). It moves `WORK_ROOT` — to `~/Library/Caches/app-packager/workspaces` on macOS, `${XDG_CACHE_HOME:-~/.cache}/app-packager/workspaces` elsewhere, `APP_PACKAGER_CACHE_ROOT` overriding the cache root — only when the path contains `/node_modules/`, printing one `[INFO]` line on **stderr** — stdout is the panel's JSON channel (`web.js` parses the whole of the `sdk status` / `profiles` stdout), so the same line on stdout broke the SDK card with `无法解析 sdk status 输出：Unexpected token 'I', "[INFO] 工作区改"...`; the relocated real path (never a symlink back into the plugin) is what reaches HBuilderX, a work root outside `node_modules` is left exactly as it was, and `engine.test.sh` pins both cases, the stderr-only rule and both call sites.
- **A parallel build no longer looks frozen while it waits for HBuilderX** (engine script version `2026.10.10.6`). `render_parallel_queue` opened with `[ -t 1 ] || return 0`, so with a pipe for stdout (the panel, CI) the whole queue table was dropped and minutes could pass with no output after `构建队列`; a non-TTY now gets `_parallel_render_queue_plain`, one line of `android 35% 等待 HBuilderX 名额 | ios 70% Xcode Archive 中` built from `status/*.json`, reprinted only when it changes or after `PARALLEL_QUEUE_HEARTBEAT_SECONDS` (default 30). The second silent stretch was `ensure_hbuilderx` queueing for the single HBuilderX compile slot without writing any status: `with_semaphore` now honours `SEMAPHORE_WAIT_MESSAGE` and rewrites the task status every `SEMAPHORE_HEARTBEAT_SECONDS` (default 15) with `…（已等 Ns）`, so a platform waiting its turn says so instead of showing the previous message. Measured on this machine: iOS held that slot for 2m12s while Android waited the whole time.
- **The `Shell 桥接` row no longer reads `undefined · /bin/bash`.** The host half nests the resolved shell (`{ available, shell: { kind, command } }`) and the panel read `kind` off the outer object, so the one row that says which bash the engine will run showed `undefined`; it now reads the nested value, and the panel test asserts no rendered line contains `undefined`.
- **The panel no longer goes blank the moment its data arrives.** The SDK card is a `const` evaluated as soon as `state` becomes non-null, but the values it reads (`sdkInfo` / `sdkList` / `hb` / `sdkMark` / `sdkStateText`) were declared further down the component body — a temporal dead zone, so the first render after `GET state` resolved threw `Cannot access 'hb' before initialization` and React unmounted the panel: it flashed (the `state = null` render, where every card short-circuits to `null`) and then stayed blank. Those declarations now sit above the cards, and `plugin.test.mjs` renders the panel a second time with a non-empty `state` — the path the suite never covered, which is how a blank 0.6.1 panel could ship with every test green.
- **The documented `sdk status` JSON fields now match what the engine really emits.** `packages/app-packager/engine/项目介绍.md` listed `platforms[]` with a `hint` field (the engine calls it `package`) and promised a top-level `settingsFile` that has never existed, so a script written against the documented contract read `undefined`. The docs now name the real keys (`id`/`label`/`series`/`state`/`ready`/`dir`/`page`/`direct`/`package`, `sdkRoot`, `archives`, `incompleteDownloads`), and `engine.test.sh` pins both key sets so documentation and output cannot drift apart again.
- **The human-readable `sdk urls` / `sdk text` output no longer reports the HBuilderX version as unknown** (engine script version `2026.10.10.4`). The text path never resolved the local HBuilderX app, so it printed `版本: 未知` even though the JSON path (`sdk status`, which the panel uses) read the real version from the same installation. Both paths now resolve it; a machine without HBuilderX still prints `未知`.

- Two options that were plain checkboxes moved into an *Advanced* fold, each with a one-line explanation: *HarmonyOS debug HAP* and *Keep work dir*.

### Fixed

- **A build with no project no longer dies on `请指定项目 ID`.** Omitting the project only ever meant "all projects" for `platform=all`; for a single platform the engine needs the explicit `--all`, so `app_packager_build` / `app_packager_check` without a project (or the panel's batch scope) failed before doing anything. `engineArgsFor()` now appends `--all` for every single-platform run without a project, verified against the real engine (`check ios --all` checks both configured projects).

## [0.2.3] - 2026-10-08

### Added

- **The panel now shows engine errors instead of hiding them in the log.** A check or build whose engine output contains `[FAIL] …` / `[WARN] …` lines gets an explicit box above the raw log, listing those lines and the total counts (the engine prints one `结果: errors=N warnings=M` per checked project, so the counts are summed; a run still in flight falls back to the line counts). So a missing profile, a missing p12, an incomplete iOS SDK or a missing HarmonyOS runtime is readable without scrolling, in both the failed and the partially-warned case. `web.js` exports `summarizeOutput()` and every job record carries `summary`, so the same structure is available to any other surface.

## [0.2.2] - 2026-10-08

### Added

- **`register`** registers a uni-app x project from anywhere on disk, on both surfaces: the CLI (`app-packager register <dir...>`) and the engine itself (`./打包工具.command register <dir...>`, engine script version `2026.10.08.1`). It reuses the wizard's registration code, so the written `config/projects/<id>.env` is identical; a directory that is not itself a project has its immediate children scanned. The command is non-interactive — no platform preflight, no "press enter" — and exits 1 with `[WARN] 指定目录里没有找到 uni-app x 项目` when nothing matches. Nothing outside the engine directory is written.
- **Panel: *Choose folder…* / *Add project*** — the projects card takes a directory, either typed or picked from the host's own folder dialog (macOS `osascript`, Windows PowerShell `FolderBrowserDialog`, Linux `zenity`; where no picker exists the panel asks for a typed path instead). *Add project* runs the engine's `register`, then refreshes the list. Two new same-origin routes carry it: `/api/app-packager/pick` and `/api/app-packager/project`.

### Fixed

- **Chinese project names no longer show as mojibake.** The engine writes `APP_NAME` with `printf '%q'`, and macOS bash 3.2 emits a mixture of raw bytes and `\NNN` escapes for one character (under `LC_ALL=C` it is all-octal). `src/projects.mjs` did not understand `$'...'` at all, so `app-packager list` and the panel displayed the escape text — and a plain UTF-8 read could not even recover it, because the value can contain a partial UTF-8 sequence. `parseEnvText` now decodes ANSI-C escapes, and `parseEnvFile` re-reads a file byte-wise when its UTF-8 form is lossy, so both escape shapes and hand-written UTF-8 files all decode to the original name.

## [0.2.1] - 2026-10-08

### Fixed

- **Tool schemas are valid JSON Schema again.** `app_packager_build` and `app_packager_check` declared a property-level `required: true` / `required: false`. The host forwards a tool's `parameters` verbatim to the model API, where `required` is only legal on an object schema and must be an array, so *every* request carrying those tools failed before the turn could start: `Invalid schema for function 'app_packager_build': true is not of type "array"`. `build` now uses an object-level `required: ["platform"]` and `check` declares none. `output.schema` was also the unsupported shorthand `{ type: "json" }`, which the host rejects via `assertSupportedJsonSchema` and which takes the whole plugin entry down (tools *and* panel); it is now `{ type: "object" }`. `test/plugin.test.mjs` asserts all four tools are free of property-level `required` and that `build` requires exactly `platform`.
- The web panel reads the web server with `ctx.get('webServer')` only. Touching `ctx.webServer` from a plugin that does not declare it in `inject` throws `cannot get property "webServer" without inject`, which killed plugin activation in every profile without a web server.

### Changed

- **Zero-impact principle** documented as the repository's highest-priority rule (`AGENTS.md`, `engine/AGENTS.md`, `engine/.cursor/rules/project-docs.mdc`, `engine/项目介绍.md` §14): a bug, misconfiguration, missing dependency or plugin failure in AppPackager must never affect the user's machine, software or projects — user projects are read-only, writes stay inside the engine directory and explicit output directories, the DeepSeek Harness installation and its other plugins are never modified, destructive actions ask first, and failures fail in place and leave a log.

## [0.1.0] - 2026-10-07

First public release of both packages, extracted from the original macOS-only `打包工具.command` toolchain.

### Added

- `app-packager`, a dependency-free Node CLI that materialises the packaging engine into an engine directory (default `~/AppPackager`, override with `--dir` or `APP_PACKAGER_HOME`) and forwards commands to it: `init`, `doctor`, `list`, `env`, `check`, `build`, `run`, plus pass-through of any engine argument (`app-packager ios my-project`).
- Engine directory upgrades that never touch user files (`config/*.local.env`, `config/projects/*.env`, `certificates/`, `signing/`, `sdk/`, `packages/`, `logs/`, `workspaces/`), tracked by `.engine-version`, with a generated `.gitignore` protecting signing material and per-project config.
- Executable-bit restoration for `.command` / `.sh` files, which pnpm archives as `644`.
- `dsh-app-packager`, a DeepSeek Harness host plugin registering four tools: `app_packager_list`, `app_packager_doctor`, `app_packager_check`, `app_packager_build`.
- Windows and Linux support in the Node layer: Git Bash (`APP_PACKAGER_BASH` → `%ProgramFiles%\Git\bin\bash.exe` → … ) with `wsl.exe` fallback and `wslpath` conversion, documented in `docs/zh-CN/windows.md`.
- GitHub Actions CI: unit tests plus CLI smoke runs on `ubuntu-latest` / `windows-latest` / `macos-latest` × Node 18/20/22, and a packaging job validating the published tarballs.
- The original bash engine, unchanged, including its authoritative Chinese specification `packages/app-packager/engine/项目介绍.md`.
