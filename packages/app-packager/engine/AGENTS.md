# AppPackager 项目维护规则

## 零影响原则（最高优先级）

AppPackager 的任何功能缺陷、配置错误、依赖缺失、脚本异常或插件故障，都不允许影响使用者的电脑、软件或项目：

- **只读使用者项目**：不修改、不删除、不移动、不重命名使用者的 uni-app x 源码与配置；写入只发生在引擎目录（`$PIPELINE_ROOT`）和使用者显式指定的产物目录内。
- **写入不外溢**：不碰 shell 配置、`PATH`、全局 npm 包、系统设置和其它应用的数据目录；不擅自安装或升级 SDK、证书、ohpm 包与全局工具。
- **不碰 DeepSeek Harness 本体**：不修改 Harness 安装目录、profile 配置和其它插件；插件故障最多只让自己失效，不能让 Harness 报错、掉工具或整轮对话失败。
- **破坏性动作先确认**：删除、覆盖、重签、上传、发布之前必须先确认；失败只报错并留日志，不回滚、不删除已有产物。
- **故障就地失败**：任何异常只影响本次任务，使用者现有的项目与本机环境保持原样。

## 文档与读取规则

- 每次修改 AppPackager 的脚本、配置、项目读取方式、权限、依赖、操作流程、产物结构、签名规则或 GitHub 上传规则，都必须同步更新 `项目介绍.md`。
- 更新 `项目介绍.md` 时，至少检查“最后更新”、软件版本、项目配置方式、权限清单、操作流程、产物路径和注意事项。
- 如果改动没有同步更新 `项目介绍.md`，该任务不应视为完成。

- AppPackager 是独立新项目。任何脚本、配置、文档和自动化都不得依赖、读取或引用旧打包项目。

- 项目读取逻辑必须保持：初始化时自动发现同级 uni-app x 项目，并支持手动输入其他绝对路径；主菜单缺少项目配置时应提示修复。
